# 应用加载与渲染提速计划

## 目标

- 打开应用时先显示基础界面，避免在冷启动阶段同步加载编辑器、可视化编辑器和完整 Plus Markdown 渲染链。
- 打开 Markdown 文件时先显示可读的快速预览，再在后台替换为完整渲染结果。
- 减少读取文件后的重复 IPC 和阻塞操作，让目录树刷新、工作区标题索引等后台任务不挡住首屏内容。

## 范围

- 前端组件分步加载：源码编辑器、可视化编辑器按视图模式动态导入。
- Markdown 渲染分步加载：先用轻量本地 renderer 输出安全快速预览，再动态导入 edition renderer 完成 Plus/Lite 渲染。
- 文件打开流程优化：已知文本文件优先读取内容，目录树和标题索引后台刷新。
- 大纲提取前移到前端本地扫描，避免打开文件后把完整内容再次发给后端只为提取标题。

## 非目标

- 不改变 Markdown 最终渲染能力和 Plus 设置项。
- 不改动文件格式、草稿格式或保存逻辑。
- 不做大规模 UI 重构。

## 兼容性与风险

- 快速预览只覆盖标题、段落、列表、引用、代码块等基础结构；完整渲染完成后会自动替换。
- 导出 HTML 仍使用完整渲染结果，快速预览阶段会先清空可导出的旧 HTML，避免导出上一份文件内容。
- 源码/可视化编辑器首次切换时会有短暂加载状态，之后复用已加载组件。

## 验证计划

- 运行 `npm.cmd run check` 检查 Svelte/TypeScript。
- 运行 `npm.cmd run build:plus` 验证 Plus web bundle 可构建。
- 运行 `cargo check` 验证 Tauri 后端签名调整可编译。
